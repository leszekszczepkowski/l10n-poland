Poland - Housing price registers for developers

This module prepares the daily price file for the Polish housing price register on dane.gov.pl and publishes it at fixed public addresses.

  • Developer (fields A-C), project (D), stages with the escrow account and the information prospectus, units with prices approved by a person.
  • A unit of a stage without an open housing escrow account cannot go to the register; sending also needs the prospectus URL and a switch.
  • Every day one CSV file per project is created once and never changed. A growing harvester XML lists all daily files as separate resources, as the instructions of dane.gov.pl require.
  • Only approved data is sent. A change removes the approval, and the file keeps using the last approved version until a person approves again.
  • Approved prices and daily files are append only.
  • Issues (price in the offer differs from the register, a unit on offer that is not sent, a sold unit still marked, the prospectus does not respond, missing file in the morning) become an activity for the responsible user.

Public addresses (no website module needed):

  • /rejestr-cen/<developer>/dane.xml and dane.md5 for the harvester,
  • /rejestr-cen/<developer>/<file>.csv for each daily file,
  • /rejestr-cen/<developer>/najnowszy-<project>.csv for the latest file of a project.

Important

This is an alpha version, the data model and design can change at any time without warning. Only for development or testing purpose, do not use in production. More details on development status

Use Cases / Context

Since 11 July 2025 every developer in Poland has to publish the offer prices of flats and single-family houses on the national open data portal dane.gov.pl, at least once a day (art. 19b of the Act of 20 May 2021 on the protection of the rights of the purchaser of a residential unit or a single-family house and the Developer Guarantee Fund, added by the Act of 21 May 2025, Dz.U. 2025 poz. 758). Since 11 November 2026 the data has to follow the structure set by the Minister of Digital Affairs (amendment Dz.U. 2026 poz. 1077): 57 fields (groups A-J), collected by the portal from a harvester XML file published by the developer.

Configuration

  1. Give users the group Housing price register: Approval (or Read). The administrator gets Approval at installation, so the menu is visible at once; remove it if another person approves the register.
  2. Set the system parameter l10n_pl_housing_price_register.base_url to the public https address of Odoo, e.g. https://erp.example.com. Every daily file keeps this address forever, so no file is created without it. Instead of the parameter you can freeze web.base.url (web.base.url.freeze = True); an unfrozen web.base.url is not used, because Odoo rewrites it when an administrator logs in. Choose this address once: files already published keep the old one. dane.gov.pl calls the addresses without choosing a database, so with more than one database set dbfilter (or db_name) to serve the right one.
  3. In Price register > Developers create the developer for the company (Fill from company copies what Odoo already knows), fill fields A-C and approve them.
  4. Create the project with its location (D), its stages and units. Link a unit to a product to compare the register price with the sales price.
  5. On each stage enter the escrow account and the prospectus URL and turn on Sending enabled.
  6. Send the address of dane.xml and dane.md5 to dane.gov.pl to connect the harvester.

Usage

  1. Mark the units that are on offer as In register, enter the price and the date from which it is valid, and press Approve price.
  2. The scheduled action creates today’s file once, after midnight Polish time. Create today’s file does the same by hand. The Today’s file tab shows what goes out and why a unit is left out.
  3. When the price changes, enter the new price and its date and approve it. A price approved in advance is used from its date. When several approved prices are valid on a day, the most recently approved one goes to the file, the same one the unit card shows.
  4. When a unit is sold (developer agreement signed), set its offer state to Sold: it leaves the next file.

Approving works through the approve buttons of the web client. Calls to action_approve through JSON-RPC or XML-RPC are refused, so an integration or an AI connector cannot approve prices on its own. This is a guard against RPC clients, not a proof that a person clicked: anyone with a session can still call the button route.

The source value is the gross price of the unit (E5). The price per m² (E3) is calculated from it and rounded to the grosz, so E3 × floor area can differ from E5 by a few grosze.

Saving the same values again (an import, an integration) keeps the approval; only a real change sends the data back to approval. A stage with approved prices cannot move to another project, and a unit with approved prices cannot move to another stage. A project that sends data cannot be archived before sending is turned off on its stages.

A daily file is never changed or deleted. If a published price was wrong, approve the correct price; it goes out in the next daily file.

Known issues / Roadmap

  • The column names follow the draft regulation of the Minister of Digital Affairs of 23 September 2026. Before production use compare the 57 headers, their order, types and required fields with the regulation published in the Journal of Laws and with the current sample file, then raise the structure version in models/structure.py.
  • Year change: the dataset title shows the year of the last file and one dataset keeps all resources. If the dane.gov.pl instruction requires one dataset per calendar year, group the files by year with a stable identifier for each year. To be checked before 31 December 2026.
  • Columns F, H and I (part of the property, rights, other payments) are entered once per stage and go to every unit of the stage; a unit has one appurtenant room (G). When parking spaces or storage rooms have different prices, move these columns to the unit.
  • Bridge modules for real estate apps that already keep units, prices and sales states (override _hpr_offer_price, _hpr_is_sold, offer_state, area).
  • Today’s file is created once, at the first run after midnight. A price approved during the day goes out in the next day’s file. A correction file for a day that was already published is not supported yet.
  • A day on which the server did not run stays without a file; it cannot be created later.
  • The fixed address najnowszy-<project>.csv keeps returning the last file, also when the project stopped sending long ago.
  • Units and stages with approved prices cannot be deleted or archived (the price history is kept). A unit created by mistake stays on the lists.
